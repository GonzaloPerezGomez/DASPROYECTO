2SERVICIOS
Service
Componente que no necesita interacción con y del usuario (se 
ejecuta en segundo plano)
Puede ser lanzado y detenido a voluntad
No tiene interfaz gráfica
Pensados para realizar tareas que no interfieran con el resto de aplicaciones / funciones
Reproductor de música
Geolocalización “continua”
Envío o descarga de ficheros
…
No es ni un proceso diferente, ni corre en un hilo diferente. Se ejecuta en el mismo proceso que la aplicación.

--- Pagina 3 ---
3SERVICIOS
Tipos de servicios
Primer plano ( Foreground )
Un servicio en primer plano realiza una operación que el usuario 
puede notar. Por ejemplo, un reproductor de música.
Los servicios en primer plano deben mostrar una notificación.
Continúan ejecutándose incluso cuando el usuario deja de interactuar con la app.
Segundo plano ( Background )
Un servicio en segundo plano realiza una operación que el usuario no nota directamente. (Tema: Trabajo en Segundo Plano)
Vinculado ( Bound )
Un servicio está vinculado cuando un componente de la aplicación se 
vincula a él llamando a bindService().
Ofrece una interfaz cliente- servidor que permite que los componentes 
interactúen con el servicio

6SERVICIOS
Service
Su funcionamiento varía en función del SDK target
Si el target de la app es un SDK < 26 (Oreo)
El servicio se puede ejecutar en segundo plano, sin que el usuario sea 
consciente
Si el target de la app es un SDK >= 26 (Oreo)
El servicio sólo se ejecuta mientras :
La actividad que lo lanzó esté en primer plano (y un margen de varios minutos desde que pase a segundo plano)
Si la aplicación deja de ejecutarse, el servicio se detiene
Exista una indicación (notificación) en la barra de tareas indicando que el servicio se está ejecutando

13SERVICIOS
Service
onStartCommand (Intent intent, int flags, int startID ) debe 
devolver un valor entero en forma de constante:
START_NOT_STICKY
Si el servicio se detiene, no se reinicia
START_STICKY
Si el servicio se detiene, se ejecuta de nuevo onStartCommand  con 
los parámetros null (Dirigido a Media Players )
START_REDELIVER_INTENT
Si el servicio se detiene, se ejecuta de nuevo onStartCommand  con 
los parámetros de la última llamada (Por ejemplo, una descarga)
Esta constante ndica  qué hacer con el servicio 
si es destruido
